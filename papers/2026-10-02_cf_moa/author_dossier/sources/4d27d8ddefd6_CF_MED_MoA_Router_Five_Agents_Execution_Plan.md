# CF-MoA：Router + 五个证据操作专家的执行计划

日期：2026-09-21。状态：研究方案，尚未修改远端代码、训练模型或运行新评测。

## 0. 本轮决定

主线改为：当前合法输入 → 操作路由 → 独立专家提出证据与答案 → 有证据约束的聚合 → 原生输出。

建议工作名：CF-MoA: Operation-Specialized Agents for Medical Counterfactual Reasoning。

五个专家按“补支持、撤支持、比候选、算后果、抗干扰”分工，而不是按五个医学专科分工。R1–R5继续用于离线评测分层，不作为互斥、可直接观察的路由真值。五个专家不等于五套模型权重，也不要求每题调用全部五个。

这是对既有系统的研究设计，不意味着以下机制已经有效。简单规则与数值执行器可以继续是主要有效部件；论文的新增贡献应由操作分工、组合、路由与实验归因共同支撑，不能把现有工具的效果归给尚未验证的新提示。

## 1. 现状核对与修改边界

| 组件 | 公开记录中的状态 | 本轮建议 |
|---|---|---|
| R1 | 主入口复用诊断与规则分支，有限关系扩展尚不能支持泛用R1 | 把分派逻辑移到Router；新增独立的支持覆盖与遗漏核对操作 |
| R2 | 已有事实提取、问句范围、三值规则与剩余支持重算 | 保留执行核，增加统一证据记录与可组合的输出，不重写为长篇自由推理 |
| R3 | 已有公开目录重决策；附加校正/投票的独立收益并不稳定 | 保留强目录基线，另测固定候选的局部反事实敏感性 |
| R4 | 给定完整生理模型、起点和计划时执行局部动作干预 | 接成有明确能力范围的工具型专家，不能假装已覆盖一般临床后果推断 |
| R5 | 旧F仍是可运行参考；后续若干学习/门控候选未替代F，固定假设改前提的监督计划尚未训练 | 保留F作强基线；只开发一个有保持与应变双向验收的受控扰动候选 |

资料依据见文末[S1]–[S6]。不应把已暴露开发结果称作全新的独立临床验证；也不应因为历史使用过开发数据就放弃所有已有组件。

## 2. 三条实现原则

### 2.1 角色独立，不要求底层代码完全独立

A1与A2可以共享规则解释器、事实表示、引用定位和答案组装器，但A1不能只调用A2/A3然后转发。每个专家应有自己的输入核对、操作目标、可追踪中间产物、最终提议和独立测试。

### 2.2 统一外层合同，不强制同一种内部算法

A2可以主要执行规则，A3可以主要评分，A4可以主要调用求解器，A5可以主要做受控多视图推断。共同点是接受相同合法上下文、交付同一种提议封装，并明确自己的覆盖与证据类型。

### 2.3 聚合有实际作用，避免“MoA只是换名的switch”

至少在需要互补操作的样本上，最终决策必须实际使用两个专家的证据。单选Router可保留为低成本对照，但不能靠这个版本证明多专家协作增量。无需强制每道题协作；应报告激活分布与多专家子集表现。

## 3. 系统结构

```text
当前病例、问题、实际检索上下文、原生答题格式
                │
          本题原方法初答（可选）
                │
     InputPacket：本题临时输入封装
                │
     Router：能力检查 + 需要的证据操作
                │
         首轮选择1–2个可用专家
     ┌──────────┼──────────┐
     A1         A2         A3       A4       A5
   补支持     撤支持     比候选   算后果   抗干扰
     └──────────┼──────────┘
           AgentProposal集合
                │
       程序检查 + 有证据约束的合并
                │
        必要时至多追加一次定向检查
                │
      完整原生答案 + trace + 实际成本
```

Router和合并器属于控制层，不增加“第六个医学专家”。同一个骨干可以承担五种角色及控制层调用；每次调用仍应计费、计tokens与时延。

### 3.1 Router只能看什么

可见：当前题面、原生选项、已允许的检索文献、当前题初答、公开工具能力、预算与明确给定的模型参数。

不可见：R标签、分类理由、gold、隐藏的另一端病例、另一端答案、作者答案解释、以来源ID推断答案的旁路。

静态端点不一定包含“此前发生了什么”。因此Router判断“当前是否值得做支持核对/候选比较”，而不是假装知道它属于官方哪种变化类型。题面本身显式提供的前后状态、干预或病史当然可用。

### 3.2 初始路由规则建议

| 可见的推理需求 | 主专家 | 可选第二专家 |
|---|---|---|
| 初答可能漏选、判断覆盖不足或证据未绑定 | A1 | A2或A3 |
| 旧主张存在前提/例外/范围冲突 | A2 | A1或A5 |
| 两个诊断/选项接近，需解释区分依据 | A3 | A1或A2 |
| 问题要求干预后果且有完整可执行模型输入 | A4 | A2或A5，须有实际对应操作 |
| 存在允许核对的干扰、来源归属冲突或呈现敏感性 | A5 | A1/A2 |

这些是待验证的初始政策，不是标签分类器。先做可复现的规则/短提示路由，再根据开发集的专家互补矩阵决定是否需要小型可学习Router。第一版不做强化学习Router。

## 4. 统一接口

以下字段与文件名是建议新增的合同，不宣称已存在于仓库。

```python
from dataclasses import dataclass, field
from typing import Any, Literal

@dataclass
class InputPacket:
    request_id: str
    native_input: dict[str, Any]
    question: str
    retrieved_context: list[dict[str, Any]]
    answer_schema: dict[str, Any]
    baseline_answer: Any | None
    available_tools: list[str]
    budget: dict[str, int]

@dataclass
class AgentProposal:
    agent_id: Literal['A1', 'A2', 'A3', 'A4', 'A5']
    applicability: Literal['supported', 'partial', 'unsupported']
    native_proposal: Any | None
    claims: list[dict[str, Any]] = field(default_factory=list)
    requested_changes: list[dict[str, Any]] = field(default_factory=list)
    unresolved: list[str] = field(default_factory=list)
    checks: list[dict[str, Any]] = field(default_factory=list)
    cost: dict[str, float] = field(default_factory=dict)
```

`claims`至少区分：本患者事实、一般医学知识、假设探针、真实工具输出。建议包含患者/文献引用、时间、极性、目标选项、支持状态、适用范围。

`checks`的类型应明确为`program_execution`、`model_assessment`或`format_validation`。引用能定位不等于引用蕴含结论；一个模型复核通过不能伪装为确定性验证。

`native_proposal`可以是单选、多选、诊断标签、NLI标签或结构化数值答案。不得把不同原生任务全部强改为同一个四选一。需要Errors等辅助字段的任务应保留完整输出合同。

## 5. A1：支持补全专家——独立于Router的新head

### 5.1 目标

回答“当前题中有哪些已给事实及合法知识，尚未充分进入候选判断”。它增加的是决策中的有效支持，不是编造新的患者检查结果。

### 5.2 最小实现

1. 绑定问题的对象、动作和范围；保留完整病例与原始来源。
2. 对原生候选、合法公开目录候选或模型提出的有限候选建立支持覆盖表。
3. 区分：当前病例已有但可能未利用的事实；已有一般知识缺乏患者绑定；一般知识确实不足。
4. 第一版只在已有上下文中重读与绑定；追加检索作为单独实验臂，检索只能补一般知识。
5. 生成有引用的支持提议和独立原生答案。明确支持增强不自动等于确诊。
6. 可选一个最小删证据探针，测模型是否确实依赖该证据；探针病例与真实病例分开，不能按模拟答案直接给原题改gold。

### 5.3 真正区别于旧R1的地方

旧入口选择哪个既有head；新A1自己产生“候选—患者事实—知识条件—问题范围”的支持覆盖记录，并能独立完成重判。A1可以使用共享执行库，但不能转发A2/A3答案来冒充自己的操作。

### 5.4 文献借鉴

EA-RAG的覆盖审计与定向补缺；CDEG的missing/ignored evidence区分；MediEval的患者支持和医学真实性分离。只借这些部件，不搬完整长程图记忆或训练流水线。[P1][P2][P5]

### 5.5 验收

与旧R1分派、同预算重答、同预算标亮证据、同知识同规则单agent比较。报告漏选修复、无依据新增、未知误当肯定、来源绑定错误。解释没有提到某事实不能直接证明模型内部没有利用该事实。

## 6. A2：支持撤销专家——保留规则强项

### 6.1 操作

逐候选、逐路径检查条件和例外，撤回明确失效或不在问句范围的支持，然后重新汇总仍有效的独立路径。未提及不自动等于否定，撤回记录不等于明确反证。

A2的目标是审计失效支持，但最终输出仍遵守完整任务政策；不能为与A1“看起来互斥”而把既有完整支持重算强改成只删选项。

### 6.2 复用与新增

保留当前事实表示、范围处理、三值执行和UNKNOWN策略。新增的主要是逐路径变更记录、剩余支持、覆盖状态与统一接口。复杂的自由生成因果图不是第一版必要条件。

MedGuideX的可执行指南和CDEG的blocking evidence可用于解释及设计机制对照，但现有规则不是借了论文术语就变成新的算法。[P2][P4]

### 6.3 验收

同facts、同rules、相近预算的模型执行器；同覆盖常数None；只删不重算；完整剩余支持重算。分开报告原R2中全部撤销和仍有有效支持两侧，不以多数类总分替代结论。

## 7. A3：候选比较专家——有方向的局部反事实检查

### 7.1 保留强基线

固定公开目录、原骨干候选评分、确定的名称映射。格式修正收益、目录收益和新增反事实检查收益分别归因。

### 7.2 新候选机制

固定当前合法候选a、b，用同一种语义对齐后的分数定义：

`margin(x) = score(a | x) - score(b | x)`

对当前可见证据e进行一次经过程序边界检查的局部编辑：

`delta(e) = margin(x) - margin(edit_e(x))`

模型只提出span_id、操作和替换内容；程序应用补丁并检查未授权片段未被改写。删去一条记录和显式改成否定必须是不同操作。必要时核对与其他句子的冲突，局部差分正确不保证医学可实现性。

第一版每题只检查1–2个关键证据，不生成大批完整病例。使用相同的候选身份、评分合同和代码映射，不比较两个不同自由生成诊断字符串的置信度。

最终仍对完整原题作答。delta是模型的证据敏感性信号，不是估计的真实临床因果效应，也不要求删除任何支持都翻转答案。

### 7.3 近邻与历史

CFDX有反事实病例编辑与CPG，并已有分诊、多专科和裁决结构；本方案不是首次提出CF医疗多agent。作者代码可用于借鉴编辑、评分与trace，但需保留上游许可并区分忠实复现和轻量改编。[P3]

项目历史已试过CPG/Adapter，不应将再次尝试描述为全新发现。新试验的意义仅在于当前单端点原生协议、固定候选的有方向差分和严格局部编辑是否带来增量。[S1]

### 7.4 验收

单次目录、相同次数重评分、旧校正、随机/无关编辑、关键证据编辑。若关键编辑不超过同预算控制，保留旧目录head，不把无效检查作为主贡献。

## 8. A4：后果执行专家——工具型agent，不重写求解器

### 8.1 两层边界

前层：从明确给定问题编译目标变量、时点、干预动作、单位和约束。

后层：调用已有明确模型，保留相同起点及未改变条件，执行事实/反事实并读出后果。

统一交付`native_proposal`、目标量、差值、动作补丁、真实执行trace、适用条件。已有inline模型估计与工具计算值保持分离。

### 8.2 覆盖规则

只有明确模型、参数、完整初始状态和必要外生输入齐备时，启用数值执行。模型未知或信息不足则返回不支持该工具操作，并让系统按普通原生推理路径回答；不能自行生成患者真实SCM冒充已知模型。

可后续增加“题面明确给定有限因果规则”的执行后端，但作为新受限能力单测，不推断其等于一般临床因果推断。不要为了五个head表面一致，丢弃已经有效的数值执行器。

### 8.3 验收

局部动作编辑 vs 同工具整计划重建 vs 无工具同预算语言重答。原v5的13条HIV任务与补充生理模型实验分开报告；后者不补写前者的成绩，也不合并为一个通用R4准确率。[S4]

## 9. A5：抗干扰专家——区分保持与应变

### 9.1 不重新走的路线

不把低答案方差等同正确，不无条件保留初答，不把人口学属性都当作无关，不删除全部“看起来不相关”的病例事实。旧F作为可运行强基线保留；旧提示复核、语义删减、高维迁移和门控失败不因改名字而清零。[S5]

### 9.2 推荐第一版：受控多视图重判

1. 保留完整原题作为锚点，记录原生语义答案及辅助字段。
2. 从有明确资格的变换库选择少量视图。最容易程序核对的是选项代码一一重映射、允许的呈现变化、已标注为非患者事实的外部材料排列；每种变化都须满足具体任务的语义约束。
3. 病例数值、单位、否定、时间关系、主体、目标问题以及知识编辑任务的指定变化保持；不能用自由摘要代替原题。
4. 分别推断并把答案映射回相同语义空间。逐个记录哪些视图有效、哪里发生分歧，而不只输出总票数。
5. 对分歧定位到具体患者事实、外部文献或选项映射。允许一次带原文的定向复判；不能仅因某答案更稳定就赋予医学正确性。
6. 输出完整原生答案、合格视图集合、分歧及未解决项。没有合格视图时使用F/原生路径，不伪造“已验证不变性”。

这仍是待验证的推理时机制，不保证优于F。其可主张的增量是合格变换、语义对齐和分歧处理，而不是多次采样本身。

### 9.3 最重要的验收门

使用两组不同的评测关系：

- 只改变已确认无关的信息：两端均正确且语义答案保持。
- 保持同一问题、改变关键前提：两端均正确且按原生gold正确响应，不能变成不看前提的常数分类器。

第二组不是强行把所有R1–R4判为必须翻转；关系由数据任务合同与可核验标签确定。评测配对不进入在线模型输入。

若只改善第一组而损害第二组，不采用为新R5主head。可以继续以F作为成熟的稳健专家，并把本轮贡献限定在系统层，而不是为了凑齐五个新算法宣称R5已解决。

### 9.4 备选小训练路线

仓库已经有固定假设、改变前提的CAD辅助监督冻结计划；它不是本轮新提出的算法。可在推理时候选不够时作为独立支线完成，但不将非医学SNLI辅助数据声称为医学独立验证，也不把已有“计划”写成训练结果。其作者保持、改P/改H、原生offset/标量控制必须完整保留。[S5]

第一版MoA不依赖这个训练支线成功。

## 10. 合并器：不把五种证据压成五张票

1. 检查每个提议是否针对当前题、当前患者、当前问句范围，是否符合原生答案格式。
2. 规则/数值结果只在输入和覆盖已确认的范围内优先，不具有无条件全局权威。
3. A1新增支持与A2撤销路径在同一候选内部合并：删除一条路径不抹掉其他独立路径。
4. A3的候选偏好只能用于对应候选和同一评分合同，不能与A4数值输出、A5投票数直接求平均。
5. A5的不变性建议不能否决已确认的关键前提变化；稳定但错误不是获胜理由。
6. 如有未解决的关键冲突，至多追加一次针对该冲突的检查；否则输出全信息原生重判并显式保存不确定项。
7. 保存采用/拒绝每项提议的标识及原因。合并器不得编造新患者事实或把模拟视图里的事实写回原题。

这是一套设计政策，需要与多数票、直接选最高自评置信度、通用LLM合并、单一全工具agent比较，不预设它更好。

## 11. 贯穿例子（虚构规则，不是临床用药建议）

已知选项A可由X或Y独立支持，选项B由Z支持。当前病例明确X为假、Y为真、Z为真。初答只选A。

A1发现Z已经给出且支持B，提议补B。A2检查A时撤销X路径，但保留Y路径，不能因此删A。合并器得到{A,B}。

若问题改为“只考虑X对应风险”，则Y不在当前范围，A的保留依据失效。A5不能因为“不要改答案”把A锁住。

此题无需A4。另一个明确提供模型和干预计划的问题才启用A4，移动事件时删除原时点事件而不是新增副本。五个专家的完整性是职责与覆盖完整，不是每个例子都必须塞进五次调用。

## 12. 实验设计：先互补性，再证明MoA

### 12.1 第一阶段：专家资格与互补性

在明确标为开发的数据上保存各专家独立输出，构建：谁修复谁、谁误伤谁、覆盖有多少、二者组合是否增加正确答案、成本多少。对不适用专家记录unsupported而不是强制推理。

做离线oracle选择仅用于估计已有专家输出中的潜在空间，不能作为在线系统结果。若任何合法组合都不超过强单head，就优先改专家，不先扩大Router训练。

### 12.2 核心对照

| 对照 | 回答的问题 |
|---|---|
| 修正输出适配后的原生骨干/原RAG | 不加系统时的真实起点 |
| 原R1分派+现有R2/R3/R4/F | 新MoA是否超越已有效的简单工程系统 |
| 单个agent获得全部相同工具/知识/目录 | 增益是否只是多给资源 |
| 同预算重答、自一致性、Self-MoA | 增益是否仅来自额外采样与聚合 |
| 五种角色提示但没有新的操作机制 | 增益是否只是persona提示 |
| 相同专家的top-1 Router | 混合是否超越纯分派 |
| 全部适用专家+相同合并器 | 稀疏路由的成本收益 |
| 提议的稀疏CF-MoA | 完整方法 |

不是要求第一天全量跑完所有臂。先在两骨干的开发范围筛出有资格的固定版本，再做冻结后的主结果及必要消融。不得用测试结果挑臂或改门限后继续称其独立测试。

### 12.3 外部近邻

CFDX是重要的诊断子任务对照。忠实配置与轻量预算适配版应分开命名，并分别计成本。MDAgents可作自适应医疗协作结构对照。EA-RAG可作支持覆盖/检索机制对照。不能把只适用诊断的方法强套所有原生题型，再据失败宣称全面优越。

CFDX作者代码与模块本轮已查到，尚未实际安装运行；其余方法的论文机制可借鉴，不因论文公开就默认代码可直接复现。[P1][P3][P9]

### 12.4 数据协议

- 现有v5保持来源和历史身份，可作已暴露开发评估；最终新泛化主张需要未参与本轮选择且历史暴露清楚的评测。
- 原题与变体仍独立推理，隐藏另一端及其答案不能进入输入。
- 以患者/母题/前提/来源家族分组，避免变体跨集合。同模板多端不能当成独立临床病例。
- 不再任意从大来源抽少量后丢弃不利类别；全量可用集合与任何成本受限子集分别写清固定规则和清单。
- R1–R3标签可重叠；按来源×R分层，不把重叠类别相加当总样本量。
- R4模型条件实验单列，不替代原HIV任务。
- R5尚未用于模型选择的保留数据，应在专家与Router版本都固定后再用；若用于调优则更新暴露记录，不反复包装成保留集。

### 12.5 指标

原生accuracy/exact match、配对双正确、合法应变对双正确、合法保持对双正确、修复与误伤、部分选项误删/漏补、格式有效率、覆盖/回退、来源绑定错误、工具动作忠实、输入输出tokens、评分调用、检索/工具调用、端到端延迟。

自报置信度不直接跨专家比较。所谓“agent一次调用”可能包含多次生成与多次候选评分，必须按实际成本统计。

置信区间按母题/病例家族分组计算；小R4与小R2子组报告计数和不确定性，不用巨大重复模板数量掩盖证据范围。随机算法采用预先固定种子，预算与失败重试策略一致。

### 12.6 关键消融

去A1、去A2、去A3受控编辑、去A4执行器、A5换旧F、证据合并换普通投票、Router换top-1/全适用激活、单全工具agent。去专家后是否允许重新路由要预先定义并报告，避免把丢预算与丢能力混在一起。

## 13. 实施顺序及交付物

### 阶段A：先锁强基线

保存现有五方向实际入口、采用版本、候选目录、规则、工具与原生输出合同。把R1分派迁到`controller/legacy_router.py`；通过旧缓存回放检查迁移前后输出不变。旧结果不能因系统包装而被低估。

### 阶段B：统一适配器

实现InputPacket、AgentProposal、请求白名单和成本trace。为R2/R3/R4/F写薄适配层。所有真实患者事实仍保留原文，结构化信息不是唯一输入。

### 阶段C：补实际能力

独立实现A1；A5仅保留一个受控多视图候选和旧F；A3增加可关闭的局部固定候选检查；R4只补工具能力与统一输出。先用单元测试排除来源、否定、单位、选项映射及计划复制错误。

### 阶段D：测互补与组合

先专家单测，后Router/合并器；主配置每题首轮1–2专家，最多一次追加检查。先能力路由，后考虑轻量学习，不做大规模多轮辩论。

### 阶段E：冻结后验证

冻结提示、目录、规则、视图资格、预算、路由、聚合、随机种子和评分。运行完整原生评测及必要外部对照，完整保存负结果、弃用候选与所有来源范围。

## 14. 可交给coding agent的总指令

> 在不改变正式v5、原生评分与历史基线的前提下，实现一个Router+五专家原型。先核对本地真实代码位置与采用版本，不把文档中的历史失败候选当成默认。移出R1旧分派，完成统一合同和回放；随后实现独立A1及唯一A5候选。R2和R4优先复用已有效执行核，R3的反事实编辑作为独立可关闭实验臂。每个专家提交原生答案、证据来源、适用范围、修改提议和真实成本。只读取当前合法输入，禁止gold、R标签和隐藏配对端进入推理。先保存专家单独输出和互补矩阵，再接稀疏路由与有证据约束聚合。以强旧head、同资源单agent、同预算采样、top-1路由为核心对照。所有开发选择与独立评测分开；任一候选未过控制时保留其真实身份和负结果，不用重命名宣布成功。不得为了“安全”强制不改答案，也不得为了“反事实”强制翻转。交付代码、配置、逐题trace、回放测试、成本、采用/未采用说明及冻结后评估报告。

## 15. 论文主线

问题：医学反事实判断的错误可能来自证据遗漏、失效支持残留、候选比较不足、干预执行错误和干扰敏感，单一重答或无差别投票不能区分这些操作需求。

方法：按操作组织五种工具增强专家；在当前合法输入上进行稀疏选择；将来源明确的提议按范围和支持关系合并。

证据：先证明专家有互补性，再证明路由与聚合在相同资源下超过强单系统；同时报告应变与保持、收益与误伤、原生任务与条件模型实验。

边界：不是五个全新算法，不是首个医疗CF多agent，不声称语言置信度等于临床因果效果。若主要收益仍来自简单规则，就如实报告规则执行及系统组合的贡献，而不是归给装饰模块。
