## 一、先建立对整个项目的共同认识

### 1.1 我们实际在研究什么

项目研究的是：医学问题中的某个条件变化后，模型怎样据此处理支持关系并回答当前问题。变化可能是病人某项证据被加入、既有用药条件失效、候选诊断的相对支持发生变化、一个已知动态模型受到干预，或者题目出现与目标无关的扰动。合格系统既要在应改变时作出改变，也要在不应改变时保持正确；“答案变化了”与“答案应该变化”不是一回事，“两次回答相同”也不等于“两次都正确”。

这里的反事实研究范围包含源作者提供的条件改变、对照、干扰与稳健性任务，并非所有记录都是具有完整结构因果模型的严格因果识别问题。因此，本研究的统一入口是**变化对具体判断的功能关系**。五类功能标签使不同来源的题目能够按共同问题观察，同时保留各来源原有题面、选项、证据和评价任务。

例如，一个治疗问题原有两条独立适用理由，变化只撤销其中一条，答案可能应当保持；一个病例增加了某疾病的支持证据，也不一定足以推翻当前最优诊断。只按“gold 翻转/不翻转”分组会把这些细节混掉。本项目先建立五类关系与 benchmark，再观察通用和医学 RAG 系统对这些关系处理得如何，随后将最有用的专门操作组织成系统。

### 1.2 原始目标并非事后为结果发明

09-08 的原始用户方案明确提出：“从已有医学benchmark中提取CF问题，以五种可解释的功能关系重新标注，揭示按数据集名称看不到的失败模式。” 同时要求“保留原题，增加标注，不重写原benchmark”和“不同任务保留不同评分，但可以共享标签”。这些要求解释了为什么数据贡献、taxonomy 和原生评价合同应当在作者讨论中居于核心位置。

09-21 的五 agent 计划把问题推进到系统层：当前合法输入经操作路由，由专家提出证据和答案，再产生原生输出；专家按“补支持、撤支持、比候选、算后果、抗干扰”分工。原计划允许共享权重和异构内部实现，也确实希望证明多专家证据聚合的额外作用。后来的实际实验没有稳定证明全局生成聚合更优，因而最终采用稀疏的能力路由组合。**原设计目标、真实尝试与最终采用实例是三件不同的事，本文都保留。**

原请求短引、会话行号、原09-21计划和09-23修订快照见[研究路径审计](sources/77369dcb2268_research_path_audit.json)及[五agent审计](sources/2c8121d3938b_five_agent_framework_audit.json)。原计划是研究史证据，不取代今天的实际代码与结果。

### 1.4 三套编号与几个容易误解的词

| 名称 | 在本项目中的准确含义 |
|---|---|
| R1–R5 | 离线功能关系标签/评测分层，允许重叠，不是输入给模型的类别提示 |
| head | 主系统末端或特定能力分支的可调用处理模块；可含提示、取分、规则、求解器和读出，不一定是训练出的神经网络头 |
| A1–A5 | CF-MoA中的五个功能agent角色；五角色不等于五套独立权重，A1/A2当前共享一次规则执行 |
| M0/M2/M3/M4/M5/M6/M7 | 当前v5七个系统配置；M4/M5为同一MedRAG方法的两种骨干/输出配置，所以是六方法家族 |
| 数据来源M01、M02等 | 来源目录编号；例如来源M02是MedPIC-Bench，和系统M2 MedRGAG不是同一个编号体系 |
| B / strong_B | CF-MoA已经采用的五操作核心，身份为`adopted_B_five_operations_v1`；后期被拿来当强基线，并不表示它没有系统贡献 |
| F | 已采用的任务适配采样/共识读出组件；是A5内部路径，不能把“F关闭”的后来额外重答开关误读成旧F整个被移除 |
| C0–C5 | 后期完整v5对照臂的简写；B对应采用核心，C2候选无理由验证，C3有理由验证，C4增三次回答，C5联合选择；详见CF-MoA篇 |
| RCV | 后期候选验证扩展，针对固定候选池进行重新选择；不等于整个CF-MoA |
| baseline / 原方法 | 必须绑定具体阶段、代码版本和配置；历史“原M4”与结构修复后的正式M4可能不同 |
| unit / judgment / input / mapping / family | 比较单元、具体目标判断、去重可见输入、评分映射、依赖家族；数量不同，不能交替作分母 |
| frozen / 新来源 / held-out | 冻结只说明某时点后配置被固定；后来若根据该批结果再调优，新版本不能继续把该批称为未见验证 |
| 新运行 / 复用 / 离线重算 | 分别是重新调用模型、复用完全相同合法请求的已有输出、重汇总既有评分；三者都可有价值，费用和证据身份必须区别 |

### 1.5 最重要的分母与比较边界

当前v5的6,104单元展开为13,000入选判断，运行时为13,905个去重输入及15,616评分映射。ALL不是简单地把“正确输入数”除以13,905：主分数先在规定单元内对非reference原生目标取平均，再对单元等权。原题与变体的两端均正确是另一组pair指标。看到8,924个正确输入与58.2924% ALL并不矛盾，它们衡量不同对象。

同样，R1–R3合计3,678次类别成员关系，只有2,941个唯一单元。R3全包含在R1内，因此不能说我们在三个独立测试集上得到21次独立复制。R4的288个模型执行问题来自24个profile，不可替换当前13个临床R4单元；R5的208个历史组件单元也不能与完整3,600个v5 R5单元加起来称新benchmark。

当前结果最稳妥的读法是三层：**七系统基线和末端head广度证据；两个MedRAG骨干的完整CF-MoA系统证据；各head在新来源、规则探针或给定模型中的组件证据。** 三层互相补充，各自范围不互相冒充。

## 二、研究前史：从医学RAG复现到功能关系研究

前史不是当前主结果的额外测试集，但它解释了几个重要选择：为什么不把方法起名后就直接归因于新机制，为什么不用旧paired高分替代当前原生评测，为什么后来的head需要简单而有区分力的对照。以下按已执行证据回顾；历史编号只在各自实验内有效。

### 2.1 2026-08-14起：先建立可运行的医学QA基线

项目最初面对MedRGAG论文及公开代码。公开发布材料足以完整运行Direct Response行，但不足以一键精确复现Table 1全部方法：部分检索材料、精确语料/index版本、GPT快照和配置缺失，代码也有占位路径与接线问题。真正完成的直接回答复现覆盖7,663题，包含MedQA-US 1,273、MedMCQA 4,183、MMLU-Med 1,089、PubMedQA 500和BioASQ 618。

按发布代码解析规则，宏平均为65.38%，对应论文66.64%；严格答案解析宏平均为63.87%。严格解析与宽松发布解析不同，422条输出不能提取单一合法选项，其中不少输出被512-token上限截断，但发布解析的宽松正则和回退仍把部分算对。又按论文附录的另一套提示/temperature做了完整敏感性运行；两个配置必须分别保留，不能挑较高列冒称同一次严格复现。

后续建立的all-Llama MedRGAG是本地变体：将所需生成、筛选和reader角色放在本地Llama链条上，以便实际运行与调试。它继承MedRGAG思想和记录下来的流程，但不同于原论文混合GPT/Llama设置。早期full-v1曾在selection质量检查停止，没有完成后续全部阶段；随后v15和后来的原生任务运行具有自己的完成证据。“有一个旧失败版本”与“以后没有完成可运行基线”不能混淆。

证据：[复现主记录](records/archive/medrgag_reproduction.md#record-0258)、[MedRGAG方法记录](records/baselines/medrgag.md)。具体复现表、解析差异及中止边界在归档原文中保留。

### 2.2 85题world-model路线：正向总分为何最终不足以支持机制

早期尝试用状态、动作和transition cards组织医学推理，再让reader读卡片或planner排序。85题上曾看到原v15为60/85、带裁决cards+planner为69/85，看起来有明显提升。然而审阅者实际是模型代理，不是真人，制品一直标记`human_validated=false`。

为区分卡片结构与上游直接判断，之后真实执行了去planner、仅planner、普通额外推理、盲direct-Luna排序和同reader控制。完整卡片无planner为66/85，仅planner为70/85，盲模型直接排序74/85，给同一Llama reader读该排序后71/85。表面上叫“world model”的路径并没有超过更简单的直接排序。

最后进一步逐题匹配输入token、提示外壳和解码，并把170个条件输入去重为128个实际不同prompt，保证42对相同提示共享同一输出。干净matched结果为直接排序64/85、WM排序64/85；1题修复、1题误伤、83题不变。由此停止了当前实现的WM增益主张。中间几次非确定性或不一致输出也保留在记录中，最终结论来自干净匹配版本。

这段历史留下的研究经验很具体：完整系统高于弱基线，不足以证明“结构”带来额外贡献。后来的目录单次控制、R2恒None、F普通多数票，以及CF-MoA的强旧B对照，都是在回答同类归因问题。证据：[WM最终匹配与停止结论](records/archive/wm_medrgag.md)，尤其原文3190–3255行；原冻结summary与代码路径在该文可追溯。

### 2.3 CF-WM：来源合同不满足、oracle撤回与gold-free负结果

随后将问题转到反事实数据。第一轮Gate A冻结6,577条输入/gold，但源材料不足以满足当时研究计划：例如MedPIC缺官方linked-pair map，CLIR若干任务缺可用历史观测及Full-TS，部分来源授权不清。该轮是数据/协议检查后停止，不能当作已经跑过模型的负结果。

后来balanced60试跑完成，但只满足1/4个冻结推进条件。曾称M12为transition oracle，后查出构造cards时读取gold/correct candidate，故明确撤回为无效label oracle。其30/60不能作为机制上界或方法成绩。修正版换成完全不读gold的teacher-transition，并保留原错误及修复历史。

修正版最初抽320题，来自MedPIC、CLIR、MedEinst、MedCounterFact各80。dry start暴露合同和parser缺陷；17个触发调试或配对关联样本在接触正确性之前被排除，最终分析303题。因此它是gold-unseen的修正版分析，不能称为完全未接触的纯盲held-out。13臂产生3,939预测，所有方法保留同一最终ID集，失败计入分母。后检发现326条MedEinst方法输出复制占位字符串，被统一记为无效且没有看分后重生成。

结果是完整transition 20.8%，低于本地MedRGAG proxy 31.7%、直接排序30.7%、无transition结构控制27.1%和等token推理26.7%；shuffle控制反而优于完整transition。模型裁判对100张卡、1,567个claim的检查也发现引用与支持不足。这条路线没有建立独立world-model效果，后来转向更局部、更容易验证的分数和支持操作。

证据：[CF-WM归档与撤回说明](records/archive/cf_wm.md)。修正版报告从Git提交`b714735`恢复，同名当前`results/summary.md`后来已被DeltaRev使用，所以不能只按文件名读今天的内容倒推历史。

### 2.4 从DeltaRev到Adapter：强信号在哪里，哪些新机制没有成立

这一系列主要使用MedEinst配对病例及构造的四选项诊断协议。开发/校准资料反复复用，各次提交不是相互独立的复制；也不是后来v5的独立原生输入合同。

| 路线 | 规模与实际尝试 | 结果与为何转向 |
|---|---|---|
| DeltaRev | 40开发＋160测试配对；抽变化、找决定性证据、选择性修订 | LLM-only delta 200/200合同失败；保守路由几乎不改答，测试0修复/0误伤；未支持有效选择性修订 |
| DeltaRank | 300开发＋300测试；四选项分数和残差 | base45.33%，残差仅+1.0pp，5修复/2误伤；提供小信号但不是强机制结论 |
| CFShift | 800开发＋200校准＋500后续配对；变化分数与疾病Profile | Profile信号强，纯shift额外+0.2pp且区间跨0；不能把Profile全部收益写成shift机制 |
| CF-KADS-MoE | 复用800/200，再1,000配对；学习融合 | Profile77.7%，融合78.5%，+0.8pp未确证；MedPIC迁移为负 |
| RiskRoute-CF | 复用800/200，另1,000测试；风险路由 | router73.3%低于Profile74.3%，未改善风险—准确率取舍 |
| CF-Residual Adapter | 400开发＋150校准＋500后续配对；Profile、CPG与基础选项分数线性融合 | 跨两接口大幅提高；基础系统的额外协同贡献未获支持，详情如下 |

Profile把患者变化与DDXPlus疾病特征关联起来；CPG利用编辑前后选项似然的变化。Adapter是额外取分特征与监督线性系数的融合，不是训练整个大模型。MA版本9维、MedRGAG版本7维，without-base版本4维，开发标签用于拟合，校准集选择正则；推理时使用冻结系数。

500对四选项协议的关键结果如下：

| 配置 | trap准确率 | pair两端均正确 | 解释 |
|---|---:|---:|---|
| MA-RAG原接口 | 39.2% | 17.6% | 此处是旧配对协议下的基线 |
| MA-RAG pair prompt | 50.2% | 30.2% | 直接看配对已有收益 |
| Profile-only | 79.4% | 42.8% | 显示额外Profile资源贡献很强 |
| MA-RAG＋Adapter | 80.0% | 52.6% | 相对原接口+40.8pp |
| Adapter without MA-RAG | 81.8% | 55.0% | 没有证明MA-RAG融合协同 |
| MedRGAG-style原接口 | 40.8% | 17.6% | 本地接口，不是论文原配置 |
| MedRGAG＋Adapter | 82.4% | 47.0% | 相对原接口+41.6pp |
| Adapter without MedRGAG | 81.8% | 46.8% | 再次显示sidecar本身很强 |

without-base是分别训练的另一组融合系数，不是把同一冻结模型某个输入即时归零。MA版本相对without-MA差−1.8pp的区间跨0，不等于已证明MA-RAG稳定有害。另一方面，shuffle delta/Profile/CPG明显降低得分，说明这些信息确实被利用，不能因为没有协同就把全部Adapter成果抹掉。

旧协议允许读取control、trap、delta，并构造受控四选项；当前v5每个端点独立回答，开放诊断不能按gold添加候选。因此旧80%以上成绩不能搬进当前主表。当前R3可以继承“有限候选取分”的思路，但候选、可见信息、参数和证据都要按新合同重新定义。证据：[连续方法归档](records/archive/cf_method_trials.md)、[Adapter实现与结果](records/archive/cf_residual_adapter.md#adapter-implementation-clarification)、[当前适用性分析](records/research/optimization.md#adapter-current-classification)。

### 2.5 09-07原生五来源全量比较：为什么要换一个观察维度

接下来完成三方法M0/M1/M2各25,280唯一输入，合75,840预测、82,131条方法×评分记录。M0/M1各保留5,832已有预测，补19,448；M2已经完成的整条上游链原字节复用。五来源为MedEinst、MedPIC、CPV-MedQA、Cultural Cues、MedCounterFact，另有冻结60对四选项敏感性协议。

原生指标显示明显异质性：MedEinst canonical match为M0 10.93%、M1 7.75%、M2 8.26%；MedPIC exact-set为35.97%、36.83%、30.84%；CPV准确率为61.59%、63.78%、67.09%；Cultural为62.53%、61.53%、66.13%；MedCounterFact EA为66.31%、61.87%、66.50%。M2并非在所有来源都提高。某个方法的原题到变体drop较小，也可能因为它两端都较差，不能自动称更可靠。

这些结果首先证明原生流程可以完整运行，同时提示“按来源看分数”仍不足以解释功能失败。后来的R1–R5分类是进一步把不同来源中的支持增加、撤销、候选变化、后果推导和保持需求抽出来。这个转向与09-08用户的原始五类方案一致，不是看最终B哪个类别好才重新标注。

证据：[原生全量比较](records/archive/native_baseline_screening.md)，原文1893行后的完成表、原生评分、配对效果和复用账；这些25,280输入与当前13,905输入是不同阶段，不能求和作为当前每方法测试规模。

## 三、数据：从来源收集到五类统一评测

本篇解释数据工作实际做过什么、为何这样做及其限制，供未参与实验的作者共同使用。这里的“反事实”包括患者条件改变、题内假设、证据干扰和知识编辑等来源任务；它们并不都等价于可识别的个体临床因果效应。R1–R5 是五种判断功能的标签。M01–M26 是数据来源编号，与实验方法的 M0、M2 等编号是两套命名。一个“比较单元”通常是一条实际变体及其来源参照关系；“判断”是其中某个具体目标；“输入”才是一次可供系统作答的问题。这三个层次贯穿后续统计。

### 3.2 五类体系具体标什么

五类描述“这次变化对这个判断提出什么要求”，不是五个训练出的分类器，也不要求互斥。下列例子均解释已经保存的判定，不是本篇新增病例或新实验；尤其 R4 的 LabTest 例子有分类意义，却没有进入最终 v5。

| 功能 | 通俗定义与必要边界 | 留存具体实例 |
|---|---|---|
| R1 新增支持 | 新信息确实给某项判断增加此前没有的依据；相容支持不等于足以确诊。 | MedEinst `case_10000:review_target_0` 新增呼气哮鸣，支持支气管炎候选；不能据此宣称唯一诊断。 |
| R2 撤销支持 | 可指出原先哪条依据，以及它为何明确失效；撤掉一条理由不等于所有风险消失。 | DiversityMedQA `GenderDataset.csv:row169:source852` 将男孩改成女孩，撤销支持 Lesch–Nyhan 的一条人口学依据；其他表现仍在。 |
| R3 重新比较 | 至少两个可识别候选，其相对支持因变化需要重估；答案翻转本身不构成证据。 | MedEinst `case_13249:review_target_1` 将自发性气胸史替换为深静脉血栓史，影响气胸与肺栓塞的比较。 |
| R4 推导后果 | 改变前提后，经有依据的关系推断尚未直接给出的结果。 | LabTest `question_41:review_target_0` 询问从未使用 fenofibrate 时 HDL 是否仍为 77.6；标签不提供精确反事实数值。 |
| R5 保持判断 | 有实际变化，但有理由认为某个指定目标应保持；相同答案不是充分判据。 | CPV-MedQA `medqa_00001:variant_02` 改变族群描述，化疗及耳毒性证据保持，所问药理机制应保持。 |

[定义、正例与已纠正反例](records/data/classification.md#L142)

标注先确认原生问题和比较轴，再对照全部相关上下文，记录 `change`（谁的什么条件改变）、`target`（具体判断）、`labels`、`rationale/evidence`（关系及原文定位）和 `cannot_infer`（不能扩大推出的结论）。官方没有配对，就不能擅自拼一个参照；题内“不治疗会怎样”与外部人口属性变化是不同轴。删除“有症状”不等于明确“无症状”，社区讨论疾病不等于亲属确诊，新增相关信息但最终答案恰好相同也不自动成为 R5。[标注合同和比较轴](records/data/classification.md#L118)

先判子目标，再取父单元标签并集。例如 `case_10000` 的一个目标是新增哮鸣支持支气管炎，另一个目标是急性喉炎与支气管炎的重新比较，因此同一单元可有 R1/R3；原喉部描述不再出现，仍不足以加 R2。MedPerturb 的就诊、管理与资源需求三个任务也必须分别判定，不能把前两者的标签自动传给第三者。“关系成立”“可以按当前任务评分”“作者答案可靠”“系统答对”是四个不同问题。

### 3.3 从初标、纠错到 v2/v3：为什么数字曾多次变化

首轮将若干大来源限为 2,500 单元，冻结 28,243 单元、80,910 个判断；其中含 2,497 缺图元数据。用户允许适度缩减，但 2,500 是助手选择，没有统计功效或代表性证明。审阅方式实际为 603 单元逐项语义审阅、13,464 分组语义审阅、14,176 结构核验；分组共读不等于为每份病例重新做临床诊断，记录没有宣称临床专家验收。

审核确实发现了错误。初始固定抽查 88 个判断，再按发现的规则扩查 99 个，共 187 个：83 支持、92 明确问题、3 待复核、9 原参考待核。目的扩查集中检查疑似问题，不能把这个比例当全库错误率。随后修改 172 个判断、涉及 130 单元：临床类 129 项、AMQA 30 项、原参考相关 13 项；149 项撤下缺乏依据的标签，23 项保留或重新确定标签，另有 11 个原参考禁用评分。两轮涉及 252 个不同判断，不能直接把 187 与 172 相加。[实际修改及前后证据](records/data/construction.md#L1487)

典型错误是把“夜间更难呼吸”读成“比患者过去更重”，或把原病例已有的夜间症状当新支持。AMQA 的 NBT 检测问题原已明确所问功能，新增泛称遗传病家族史并不改变检测—功能关系，于是从泛化的 R1 改为具体目标的 R5。另一些目标确实应保持，但作者 gold 有问题，正确做法是保留语义标签、单独禁用参考评分，不能直接改写原答案。更早还有一轮 704 个 AMQA 单元的可实施性裁决修正，与上述 172 个判断范围有重叠、单位不同，不能相加。复审确认这 172 项标签处置已解决，不等于全库 gold 已验证或所有质量问题清零。

9 月 9 日的 v2 是一次明确收窄：选择文本且已有固定规则可评分的 2,015 个 R1–R4 单元，再加入 CPV 全部 1,090 个合格 R5，得到 8 来源、3,105 单元、4,872 输入、每方法 6,030 评分映射。155 个需要人工/模型裁判的候选及 106 个必要图像缺失候选未纳入；开放诊断若有既定匹配规则仍可使用，并非一概排除开放回答。v2 五类可重叠，数量为 1,929/77/327/13/1,090。[v2 的实际纳入规则](records/data/construction.md#L490)

同日 v3 仅调整展示分组：按 v2 调整前固定类别数，将 328 个重叠单元分给其已有类别中最小的一类。由此得到互斥的 1,601/77/324/13/1,090，总数仍为 3,105；题目、gold、原始语义和单题正确性均未变。这解释了部分历史类别分数变化并非模型进步。后续 v4/v5 恢复完整多标签语义，不能沿用 v3 的互斥字段覆盖母库。[v3 的 328 项归属调整](records/data/construction.md#L553)

### 3.4 v4 补全与 v5 抽样：完整母库和实际测试集分开

用户随后要求补齐遗漏、复用已审 R5，不能靠数量裁剪冒充完成。9 月 10 日固定了 24,436 个抽样遗漏单元，最终其中 18,023 有合格目标；其余已记录依据不足、构造无效、五类外或评分资格问题。另复用 18,238 个旧 R5 的语义，重新判断执行资格，恢复 16,972 单元；这不是 18,238 次新标注。MedPerturb 又补 3,615 个此前遗漏的 RESOURCE 判断，3,529 个合格，并使 3 个父单元重新获得至少一个合格目标。原先未改病例、只加编辑声明的 10 个变体也被识别，旧目标恢复数因此从 16,981 修正为 16,972。[补分类、恢复与调整台账](records/data/construction.md#L2343)

v4 最终为全部 55,991 归档单元建立去向，保存 109,599 条已审判断，其中 77,781 个合格判断落在 38,123 单元、11 来源。具体适配包括按完整原题精确恢复 DiversityMedQA 选项和答案、区分文本“视图”与必需图像、恢复 MedRGB/MedCF 中间导出漏带的旧理由与原件字段。修复后的逐字段检查通过，不能把中间缺漏写成从未发生。LabTest 与 EquityMedQA 的评分接口、MedCF 的知识编辑步骤、MedMKEB 的图像仍未满足本轮合同，所以这四个取得来源没有进入正式比较。

R5 完整合格池有 35,872 单元，明显大于其他类别。曾预览删除七个完整来源、以及 3,000/3,500/4,000 比例预算；这些方案未实施。最终用户确认保留完整 v4，另建 v5：所有合格 R1–R4 目标保留，八个 R5 来源各不放回抽 450 单元，共 3,600。该设计控制来源覆盖和成本，不是最优功效设计，也不保证疾病或人口属性均衡。

抽样先固定一次随机种子，逐来源对唯一 ID 排序，再执行 `random.Random(seed+":"+source).sample(ids,450)`；不按旧预测、难度或新方法成绩选择，也不因结果不利重抽。不同来源入选率约为 3.57%–64.01%，450 个单元对应的原题根数也不同，不能称每来源 450 个独立患者。原 `labels` 保留，新增 `evaluation_labels` 决定本轮归类；未抽中 R5 的 R1/R5 单元仍可以只作为 R1 计分。[冻结抽样协议](sources/3475b2dfd66b_sampling_protocol.json)、[实际算法及字段含义](records/data/construction.md#L2467)

### 3.6 系统实际看见什么，分数怎样产生

模型只读问题、原生选项、完整给定证据、答案格式及明确预算；题号用于记录，gold、R 标签、标注理由、配对另一端答案和评分映射不进提示。原题与变体独立初始化。MedEinst 保留开放诊断；MedPIC 是原生多选；MedPerturb 按就诊/管理/资源目标展开；MedCounterFact 保留假设证据；BioRAB 保留当前前提、假说和示例；MedRGB 保留六档固定材料，100 档为参考。

本地 MedRGB 的六档材料可再追加外部检索，因此不能宣称完整照搬其官方静态证据评测。必需的扰动材料也不能被干净检索替换。各基线的语料、检索机制、骨干和预算并不完全相同：统一的是本轮原题与评分边界，不能由此宣称控制了全部资源因素。历史预测仅在题目、选项顺序、固定证据、输出预算及方法配置精确一致时复用；按题号相同复用不足够。[输入权限和精确复用](records/evaluation/protocol.md#L37)

评分先在每个单元内平均非参考原生任务的正确性，再对单元等权平均。ALL 的分母是 6,104 单元，不是五类百分比的平均，也不是对 13,905 输入平铺求平均。选择题匹配选项，多选保留集合 exact/F1，关系标签归一匹配，开放诊断采用既有 canonical 映射；不是重新请医学裁判判断整段回答。无效输出、投票平局和算法失败保留在完整分母计错。R5 的变体准确率、两端同时正确率与答案一致率分开：稳定地给出同一个错误答案不是成功。[评分与失败处理](records/evaluation/protocol.md#L67)

### 3.7 已证明的价值、质量边界及作者可追溯的证据

数据贡献是把已有来源整理为判断中心的五类体系，并实现了可检查的分类、资格、抽样、原生输入和评分链条；不是新写 55,991 道临床题。七系统配置的完整结果显示，R1 最佳仍仅 31.44%，R3 最佳 30.42%，ALL 为 47.35%–51.61%，R5 为 63.42%–73.37%。这支持研究“整体准确率掩盖了哪些任务弱点”，也是后续五 head 与五 agent 集成的起点。但这里测的是所属子集上的原生任务表现，来源、任务和类别有关联，不能仅凭低分断言模型内部一定没有执行某种思维操作。[完整七配置与 42 项指标核验](sources/13d3f2643dd3_seven_methods_audit.json)

### 4.2 为什么从基线比较转向 head，而没有直接继续堆检索

早期分类筛查发现R3、R2、R1较弱，但错误性质不同：R1/R3有大量诊断未映射，R2主要是输出合法但集合错误。抽查同时看到了括号缩写导致的匹配损失、真正不同疾病、粒度差异及多诊断列表，不能把所有未映射补成正确。R2则有更直接的过程反例：患者CrCl为70，模型却把它代入15–30区间；另一个输出将检索文献中他人的生活习惯、突变归到当前患者；撤掉晕厥支持后，又漏掉跌倒史仍支持的其他药物。这些观察促使研究从“资料是否更多”转向“事实属于谁、规则是否适用、哪个选项的哪条支持仍成立”。[诊断与文献取舍](records/research/optimization.md#L138)、[原始病例证据](records/research/r2_support_head.md#L677)。

七系统之间还混合骨干差异。为拆开这一点，实际进行了167道MedPIC×两骨干×有无同一份检索证据×三种子，共2,004次新生成，统一回答提示、schema、温度与输出预算。75道R2上三种子平均准确率分别为：Llama无检索19.56%、有检索21.78%；Qwen无检索42.22%、有检索52.44%。Qwen检索收益主要出现在66道None题，9道仍应选药物题反而从22.22%降到7.41%。Llama检索收益跨种子不一致。该实验定位了骨干/适配条件及检索作用，却没有运行七条完整上游流程，也不是新head的52.44%正式成绩。M0/M2这167题的输出均未到64-token上限，短预算也不是已证实的差距原因。[受控设计及完整结果](records/research/r2_support_head.md#L805)。

由此形成的共同原则是：先保持原骨干和真实上下文，定位最小失败环节；区分事实抽取、支持执行、候选决策和最终序列化；用同范围普通重答、同资源目录或同事实执行解释增量；同时看修复与误伤。它不要求每个head都成为独立训练模型，也不把分类R标签交给模型作oracle路由。

### 4.3 R1：新增支持的目标，以及实际交付的组合封装

R1要回答的是：新增相关信息后，系统能否利用这份支持完成当前判断。最初没有凭名称再造一个“R1推理模型”，而是先检查已研发R2/R3组件能否迁移，再补缺口。实际候选按可见任务结构分派：诊断用公开目录重决策，用药规则题用支持执行，其余保持原输出。全部2,866单位中，1,780进入诊断目录、72进入规则、1,014透传；其中新增诊断范围1,100题，新增规则62题。因此R1的有效实现是复用成熟组件的wrapper，有完整独立调用接口，而非第三套独立知识算法。[调查、扩展与交付](records/research/optimization.md#L380)。

### 4.5 R3：为什么保留目录重决策，而没有采用更复杂的证据链

### 4.7 R4：从临床机制缺失，转为给定模型下的局部干预执行

### 4.9 这些 head 如何给后来的 CF-MoA 提供方法基础

五个head提供五种功能角色，但并非五套相互独立训练参数。R1曾是组合wrapper，后期A1/A2共享规则支持核，通过增加/撤销操作区分角色；A3来自目录候选重决策，A4来自给定生理模型的局部patch，A5使用F决策组件。最初Router＋Five Agents设想包含有实质作用的聚合，后来多专家生成聚合及新增专家也真实运行过。采用的保守B主要依据可见能力选择单分支并确定性执行，不能画成五人每题同时会诊，也不能宣称所有协作承诺已验证。

这一历史解释了后期为什么集中在两个MedRAG配置做深度系统实验：它是在七系统基线和21组专项提升之后，选择两骨干实施统一路由、消融、强控制及全量v5，不是整个研究只做了两个方法。B相对两原系统完整ALL增加10.09/12.01个百分点，属于另一套真实系统结果；其R1/R2/R3分别为M4的1,279/38/390、M5的1,336/46/440，与前述专项wrapper数值不同，必须保留版本身份。CF-MoA完整各臂、保持/应变以及未采用扩展由系统篇展开。本篇依据为[五角色、源码版本及实际调用图审计](sources/2c8121d3938b_five_agent_framework_audit.json)，各head原始分数不因此被替换。

## 五、CF-MoA：五种操作、失败协作与完整系统验证

本篇面向共同作者，解释已做实验的动机、实际方法、结果、改变方向的理由和可引用证据。它是2026-10-03的研究材料快照，不是待填数字的提纲，也不替代持续维护的实验主记录。阅读顺序按研究决策展开；每次运行中的GPU轮询不逐条搬入正文，但影响方法身份、预算、结果或恢复的失败会说明。全部数字来自已经完成的运行与冻结汇总，本次没有新增模型调用、评分、训练或模拟。

### 5.1 原问题：五个head怎样成为五个agent

先前R1入口已经把诊断、规则和其他格式分派到不同路径，因此它本身不是独立“新增支持算法”。R2已有正向事实抽取、问句范围、三值规则重算及UNKNOWN继承；R3已有公开目录内的原骨干重新决策；R4已有完整给定生理模型下的局部干预执行；R5交付的是F，即任务适配后的多次采样和NLI双映射、双路径组合。把这些直接列为五个独立新算法会错失实际实现。09-21计划因此先要求迁出旧R1分派，再真正开发独立A1支持覆盖核查，并为A3和A5设计额外的受控机制。

计划中的agent由操作职责定义，不以医学专科或权重文件定义。同一个Llama或Qwen可以承担多个角色，但每次实际调用仍有成本。统一的InputPacket包含当前合法题面、原选项、许可检索材料、原生schema、必要的同题初答、可用工具和预算；AgentProposal记录适用/部分适用/不支持、原生提议、claims、requested_changes、未决问题、检查类型和成本。患者事实、一般医学知识、假设编辑和真实工具结果应分开；可定位的引用只证明文本位置，不能自动等同医学蕴含。

最初设想首轮选择1–2位专家，有关键冲突时至多追加一次定向检查，再有证据约束地合并。这个目标比给五个提示起名字更具体：需要说明最终答案实际用了哪些不同操作的证据，并对同资源单agent、同预算重答、相同专家top-1等控制取得增量。离线R标签、gold、分类理由、隐藏的另一端病例/答案、作者解释不能进入路由。静态端点往往没有显式“编辑前状态”，控制器应判断当前可见任务需要何种能力，而不是猜官方类别后查答案。

原计划也明确允许共享事实表示、规则执行和组装器，保留简单工具作为主要有效部件。原版要求独立A1有自己的支持覆盖产物，不能仅转发旧A2/A3；当这条独立研发失败后，09-23用户另行授权最简复用方案，才采用现在的A1/A2同核分解。二者是有记录的设计修订，不是第一次就完成五个独立专家协同。[原计划§0–4、§12及§15](sources/4d27d8ddefd6_CF_MED_MoA_Router_Five_Agents_Execution_Plan.md)

### 5.2 建立可信起点：锁定采用版、迁移旧路由和区分验收层次

首先逐一锁定R1/R2/R3/R4/F的真实入口和依赖，排除同目录里的失败提取器、训练标签直返、早期布尔R4和未训练CAD计划。旧R1的新控制层回放七系统各2866输入，合20062条输入、75264次缓存回调，返回值和请求逐项一致；这是迁移等价，不是75264次新推理或新泛化成绩。

A4适配暴露了一个实质配置错误：公共默认temperature=0覆盖了采用版0.7。团队暂停受影响路径，恢复完整采用profile及依赖哈希，再分别做请求一致性、同一响应的执行一致性和真实小批调用。Llama又遇到prepare与实际输入相差BOS，另一次跨异步/同步入口比较把output_kind变化误当模型参数漂移。修复观察边界后，两个骨干各4条真实请求与动作、求解器及原生输出验收完成；旧失败收据没有删除。由此形成后续共同原则：CPU能构造请求、grammar能编译、请求能进模型、完整语义输出可用、主任务得分提高，是五件不同的事。

运行器使用SQLite持久化请求意图、响应、实际参数和费用，完整请求及输入/profile一致才可复用。提交后响应缺失保留unknown，不能重抽到成功或当0成本；明确不可用与“有答案但错误”分开，完整成功率分母都保留。后期普通单题错误继续完成面板，系统性错模型、错输入、未知提交等仍需停止受影响运行。这个调整让方法能接受完整质量检查，同时保留真实失败。[报告§3](records/research/cf_moa_experiment_report.md#L101)、[主记录阶段A–C](records/research/cf_moa.md#L40)

### 5.3 独立A1：从合同不可执行到完整运行但未采用

A1最初尝试审计“哪些已知事实/合法知识尚未进入判断”，输出带出处的支持覆盖和补入建议。第一版不是低准确率，而是实际grammar兼容性失败：每骨干111条执行失败、10条不适用，共222条失败没有候选答案。遍历结束曾写complete，因此随后补上首错锁和停止门，明确complete不能等于方法成功。

兼容修复后，M5固定d00003又发生长度截断。诊断不是“答案差一个括号”：输出有重复引用、尚未完成覆盖和知识字段。A1-v2改用有界证据ID及关系合同，r1/r2排查system原生答案要求与后续审计要求冲突，r3加强关系约束，r4只检验有限结构空白，r5再将重复表达压缩为状态码。各版本分开冻结，不把提示或语义改变都称工程修复，也没有无限增加输出预算。

r5终于完成两骨干全121输入，373次实际请求。M4有91个可用提议、30不可用，M5为60可用、61不可用；其中每边10不适用，其他主要是字段容量触界，M4另3条关系无效。M4/M5正确输入为55/42，原生74单元均分40.4505%/23.0631%，低于同知识规则单答52.7027%/53.6036%及旧R1分派70.0000%/66.6667%。r5没有碰4096总上限，却不能证明触界字段语义完整；因此保留不可用，不事后删未决字段换取分数。最终不采用独立A1 r5，保留它作为后续实验池的一项明确未采用来源。

此阶段的正面交付是独立支持审计实现、严格输出/来源/成本合同及完整控制。质量结论则是这套更重的审计还没有超过简单有效组件。它不支持“所有支持补全都无效”，也不允许把修好运行器当A1方法成功。[r5终态与成本](records/research/cf_moa_experiment_report.md#L291)

## 六、把实际研究变成作者共同认可的逻辑链

### 6.1 三个研究层次怎样连接

数据层先回答“哪些变化影响了哪个判断”。五类标签是对任务的功能描述，既容纳新增证据后的应变，也容纳无关扰动下的保持。构建层把这种描述落实成具有出处、目标、资格、评分和抽样沿革的benchmark，让方法之间的比较有共同对象。方法层再回答“当前输入需要什么计算能力”：支持重算、候选比较、显式模型执行或稳健读出。R标签用于解释数据与评价，agent能力用于在线执行；二者通过研究设计联系，不通过隐藏标签直接路由。

因此，论文中的因果论证不能写成“R3低，所以必然缺某一内部神经机制；添加A3证明已经解决医学推理”。已有证据能支持的链条更具体：R3等子集整体表现较弱；错误检查发现大量候选不可达或原生映射失败；给相同骨干和上下文提供公开目录后，多个系统的有效决策改善；用名称规范、单次目录、投票和校正分开观察后，主要收益来自候选空间和读出，额外校正并不稳定。这个结论有实际机制解释，也有清楚的可复现操作。

R2的链条与此类似但不同：撤销一条条件后，需要重新计算所有仍适用的支持；自由生成整张支持图、逐药审计或全盘重答不稳定；有限规则与正向事实提取让执行可检查；增加支持与撤销支持消融均影响结果。不过总体类别偏斜使恒None成为很强的控制，所以必须同时看仍有支持的案例，才能解释我们想保留的能力。不能把R3的目录收益套用成R2的规则机制，也不能因一个简单控制总分更高就抹掉已经测得的剩余支持识别。

R4和R5则补全框架对两种不同需求的处理。R4说明在关系和模型确实已给定时，局部干预表示能够可靠驱动已知求解器；它不补造未知医学因果模型。R5说明保持正确需要受任务约束的稳定读出，同时必须保留对相关变化的响应能力。它不允许复制隐藏参照答案。每条分支解决的对象不同，适用性、覆盖和证据成熟度也不同。

### 6.2 可以直接供作者讨论的一段完整故事

> 医学反事实推理要求系统识别条件变化对具体判断的影响：有些变化引入新支持，有些使旧支持失效，有些改变候选之间的相对证据，有些需要沿已知关系推导后果，还有一些不应影响当前目标。现有医学反事实与扰动资源分散在不同任务和数据集之中，单独报告来源级分数难以揭示这些不同功能需求。我们首先整理相关资源，以五种可解释关系对原生问题和具体目标重新组织，并通过出处核验、资格审核和可复现抽样构建跨11来源的benchmark。在七个系统配置上进行完整评价后，我们发现整体成绩掩盖了支持更新和候选重比较子集上的明显不足。围绕这些观察，我们研发并验证了一组专门head，将有效的支持处理、候选决策、条件后果执行和保持读出组织为CF-MoA的五个功能agent。最终采用版通过输入能力路由选择适用操作，保留原生答案合同，在两个骨干的完整benchmark上同时提高总体得分、应变与保持表现。组件对照进一步说明哪些收益来自规则作用域、候选可达性和任务适配读出，以及何时更复杂的聚合不能带来额外改善。

这段叙述足以把数据与框架放在同一研究问题下。它没有把原始多专家聚合目标冒充已获证实，也没有把后期某个验证器当作全部方法。真实研究中的失败不是正文的主角，但它们解释了我们为什么采用现在的组件。

### 6.5 有吸引力且能被证据支持的写法

作者可以强调“统一的功能视角”“跨来源、目标级、可追溯benchmark”“从功能诊断到操作专门化”“跨七配置的末端改进”“双骨干全量系统收益”“同时改善应变与保持”。这些表述都能定位到真实工作，而不是仅有计划。

几个需要精确限定的词同样重要。“五agent”描述五个操作角色；“多agent协作带来增益”需要比单专家、同工具、同预算等控制更强的证据，目前不能直接给出。“验证”可以指已经完成的规则、病例或生理profile组件检查；“最终系统独立确认”则尚未执行，二者不要互相抵消。已见v5反馈后获得的开发提升是实测成果，只是其泛化证明力与新家族确认不同。没有必要把每次可观测改进都贬成无效，也不能用“已冻结”抹掉更早暴露。

推荐论文题目沿用：**CF-MoA: Taxonomy-Guided Benchmarking and Agent Orchestration for Counterfactual Medical Reasoning**。此前[英文框架](../framework/framework.pdf)可以作为成文组织起点；本底稿提供其完整研究材料。正式论文应由作者根据贡献主次压缩，本底稿保留他们作出这些选择所需的事实。

### 7.2 为什么不同记录看起来会矛盾

第一种是时间变化。全过程报告保留了“首错停止”“尚未完成”“等待处理”等当时状态，后面章节可能已有修复或完成。读者应按版本和日期查后续闭环，不能用最早一段覆盖整条方法的发展。第二种是对象变化。M6先指i-MedRAG，后来正式七配置中的M6改为MedGENIE；来源M06则一直是数据来源，不是该方法。第三种是协议变化。旧paired四选项、v3互斥类别和v5多标签原生评测不是相同任务。第四种是统计变化。正确输入计数、native ALL、类别均分和pair两端正确率可以同时不同，不能从某一项推算其余所有指标。

第五种是采用身份与研究候选混写。独立A1、新A5、A3编辑、F额外重答开关和候选验证都实际尝试过，但未必进入默认B；旧有效A3/F仍可被默认使用。第六种是工程准备与真实执行混写：CPU fixture或合成response验证可以证明接口行为，不能算新增医学推理证据；原始模型输出的严格缓存复用则属于合法已有证据，但不是新模型调用。这些区别直接决定作者怎样描述“我们做了什么”。
