# CF-MoA v2 审阅与效果优先的下一轮计划

**审阅日期：2026-09-23。被审阅版本的实验状态截至当日14:25（UTC+8）。**

本次对照版本2新增第11章、修订核心计划、A1/A3逐输入公开状态及归因/成本/就绪摘要。公开材料没有完整患者原文、原始模型回答和运行源码，因此没有重新判定医学正确性、重跑服务器模型或修改旧分数。以下明确区分已有事实、研究判断与建议新增实验。

## 1. 总结：方向已调整，但有效性检验仍被辅助约定截断

v2沿用了上一轮建议的“强旧系统B＋目标化补充＋局部裁决”，并完成归因、B封装、A2控制parser兼容和A3实际对照。它不是完全偏离计划；问题是旧计划中的资格、字段与暂停要求仍然过强，部分研究问题尚未得到真正实验。

**本次修改：保留有用内核和最基本实验可信性，取消以辅助审计完整性为前提的研究推进方式。研发时允许在开发集上修提示、简化输出、调整预算并继续评分；测试集上不调参。**

“本版本不进入默认系统”与“这个思路不值得继续研究”是两种判断。A1目前没有经历有效的修改裁决，应先让它完成质量实验；A3已经有小规模负结果，可以暂时降低优先级，但不能据此概括全部反事实编辑无效。

## 3. 最重要的解释修正

### 3.1 A1：没有形成有效提议，不等于医学判断六题全错

问题发生在模型自报知识来源与引用字段的组合：程序要求某类一般知识必须使用特定空引用值，但提示没有同样明确传达反向条件。两骨干同样失败，且这些输出很短，不能以此归因于总token不足或骨干医学能力。[S3]

同时，记录中也有知识条件偏离目标的现象。因此不应只删除validator就宣布修复。新版本需要同时解决：

- **结构责任交给程序。** 目标候选由调用者绑定；原文和文档ID由上下文构造器提供；不让模型反复生成可以直接复制的元信息。
- **推理责任留给模型。** 针对目标给出支持、反证或不足，并明确当前病例哪些信息相关。
- **来源不明降低证据等级，不整条作废。** 未验证的知识仍可作为模型判断送给裁决者，但不能冒充患者事实、已检索文献或已执行规则。

新头可输出短文本，或者只有`verdict / reason / patient_refs`的浅层结构。`patient_refs`可选；不必产生多层knowledge对象、未用槽位和NONE占位。短理由偏题需要在质量分析中暴露，不用复杂语义门阻止所有最终答案生成。

### 3.2 A3：已有真实负结果，但分数尚不足以定论整个机制

在八题面板上，关键编辑对两个骨干均未超过原题重评分；一方修复与重评分是同一题，另一方出现误伤。[S4] 建议暂时让旧目录核承担主角色，不继续把大量调用投到同样的编辑细节。

也有两项需要保留在解释里，而不是修饰掉：

1. M5的拟编辑有较多未通过资格；公开摘要不提供每条拒绝的具体原文原因，不能断言全是防御规则过严，也不能断言全是医学编辑错误。
2. 有一题因无合格编辑而使三臂都回退，包括原题重评分。[S5] 这是既定实现下的有效记录，但下次无编辑控制应独立运行，不能由编辑臂能否成功来决定是否执行。

进一步研究应先查：比较候选是否覆盖正确答案、被删除内容是否真是区分证据、readout是否确实使用差分。结果标签可以在隔离的开发分析中检查这些问题，不进入在线候选选择。没必要先重新建设编辑安全框架。

### 3.3 真正值得立即利用的是旧读出矛盾

归因记录表明：部分误伤在正确候选已经传给聚合器后发生；另有自报采用支持却漏掉对应选项，以及原生诊断标签被重新表述的现象。[S6]

这支持一个很具体的实验假设：**将“决定哪些选项成立”与“把决定写成原生答案”分开，可能比再写一轮解释更有用。** 它不证明这些病例一定能被修复，也不证明所有引用都有医学依据。

## 4. 放弃防御编程：实际取消哪些要求

不是先花一轮工程去重构全部安全设施。对研究分支直接选择简洁路径；已有日志和工具继续使用。

| 不再作为默认阻断 | 新的研究处理方式 |
|---|---|
| 一项辅助字段缺失、引用枚举不一致 | 保留原始响应；转换为未验证模型判断；继续完成最终回答 |
| 可选理由达到字符上限 | 不把触边等同于截断；移除小字段硬上限，保留合理总输出预算 |
| 一题输出非法，停止另一骨干或全部尾部 | 记录该题失败或按统一政策格式修复一次，继续其他题 |
| 所有预检/回放都通过才允许看开发质量 | 少量基本运行检查后就生成和评分，异常率与正确率一起报告 |
| 所有样本完整成功才能评分 | 对全部计划成员报告当前结果，未完成和不可用单列，不删除分母 |
| 新提示、参数或预算需要反复审批 | 在已授权开发范围内自主迭代，保存简要配置和结果 |
| 高置信度才允许提出任何改判 | 开发时先产生和评价提议，再研究何时调用/采纳；不先把所有分歧过滤掉 |
| 完整独立资格审计是继续开发前置 | 继续在明确开发集探索；独立集身份与最终验证随后处理 |

保留的不是产品门禁，而是三项研究必要条件：**推理不看gold或隐藏配对端；结果不篡改、不删除不利样本；当前患者事实不由模型自行发明。** 系统性错输入、错模型或数据泄漏需要停受影响实验。单题解析、可选说明和常见模型失败不应中断整个开发过程。

### 4.1 允许重试与调参，但不“抽到正确为止”

在开发中，可以根据失败类型调整新头的prompt、结构、temperature或预算，不受旧候选的“禁止自动迭代”约束。每次配置留一行记录即可，不需要重新冻结整个项目。

最终用于比较的运行预先确定格式修复/重试策略，并把同样策略给控制组：例如仅在原生答案无法解析时追加一次简短答案生成。首轮与修复结果、额外成本分开保存。不能看gold后决定哪题重抽、从多个答案中取正确者，或把改过策略的新分数覆盖旧版本。

答案字段完整而辅助解释被截断，可以在新协议中明确按完整答案评分；答案本身没有闭合、缺选项或歧义时，不能推测补齐。对旧缓存采用新解析规则属于新后处理实验，不修改旧结果身份。

### 4.2 调试与评价不要混为禁区

可以查看已暴露开发题的gold、旧错误和原始输出，用来形成新假设、改提示和定位错误。不要把“避免测试泄漏”扩大成“科研开发不能看错在哪里”。

按错误选出的样本可以作为调试集，不能拿它替代完整评测结果。最终报告回到固定完整开发面板，再在未参与选择的母题/来源上验证。

## 5. 第一项实验：短决策＋确定性原生读出

### 5.1 核心改动

模型只对候选作决策，程序把决策映射成原生答案。格式不再经历第二轮自由改写。

**多选：** 相对于基准集合B，模型提交ADD/REMOVE/KEEP。程序生成最终集合：

`Y = (B ∪ ADD) \ REMOVE`

同一选项同时出现在ADD与REMOVE时，不能偷偷选择一种优先级；允许一次简短冲突决策，或将该项记录为未解决并使用事先规定的单项回退。所有合法其他选项继续保留。

**单选、诊断或关系：** 模型返回当前合法空间中的键；程序使用冻结原生映射写出标签，不进行自由同义改名。

这不是“旧答案永远更可信”。ADD和REMOVE都开放。A2的规则结果只有在输入/范围成立时适用，模型生成的“MET”也不会自动成为客观真值。

### 5.2 优先复用哪些结果

使用全部有对应完整trace的固定开发样本，而不只挑那部分已知误伤。在完整trace中能不歧义地恢复最终决策时，先做离线读出实验；不能恢复时标明原因，不从gold填补。

若必须新增推理，则只加一轮逐选项决策。保留原始文本、专家提议和完整当前题，去掉重复的审计解释与重新措辞任务。

### 5.3 三个控制

1. 强旧B。
2. 原提议＋自由生成最终答案。
3. 相同原提议＋短决策＋程序读出。

这项实验检验读出设计，不把即使成功的结果写成A1生成了新的医学知识。诊断映射改进和集合误删减少分别报告。

## 6. 第二项实验：让轻量 A1 真正走到裁决

### 6.1 最小专家提示（建议）

```text
你只负责核对当前问题中可能遗漏的一项支持，不重新审计整个病例。

当前问题与原文：{native_input}
原生候选：{native_candidates}
需要检查的候选：{target}

给出支持、反对或资料不足的判断，解释与该候选直接相关的一条依据。
可以使用一般医学知识，但不要声称它来自未提供的检索文献，
也不要把一般知识写成当前患者已经具备的新事实。
只给简短结论和理由；已有原文引用编号可选。
```

目标由调用者传入，模型不需要重复填写目标ID、来源类别和未使用引用槽。模型理由偏离目标时仍保留为实际输出，并在后续裁决和误差分析中识别，不整批停止。

### 6.2 目标选择要服务方法，而不是沿用技术smoke捷径

当前“首个未选选项”只用来检查接口，不应直接成为正式策略。[S1] 建议使用当前合法候选中的最强竞争者或支持不足项；有现成候选分数则复用，没有则在一次短提议中选择最值得核对的候选。

先在开发面板对所有适用题产生提议，不要求先达到高自报置信度。提议是否有用由后续对照检验；新Router等有了互补数据再做。

### 6.3 检验旧答案锚定，而不是把它当成结论

新增一个有明确机制目的的小消融：A1看到B答案 vs 不看到B答案，只看到相同当前题、候选和核对目标。裁决者两种情况下都看到B及提议。

这检验是否因一开始展示强旧答案而让专家只会复述。不能预设隐藏B必然更强，更不能强迫A1一定提出不同答案。

### 6.4 首先真正完成质量实验

已有六条原始提议与完整控制答案应在服务器检查。可以先对完整保存的控制答案离线评分；对A1提议采用新来源标记和简洁裁决的实验另记版本。旧A1不因此变成成功，新的裁决调用也不称缓存回放。

新实验比较：B直返；同预算普通目标化重答；轻量A1＋短裁决。对同样的输入完整生成答案，并按原生指标评分。报告最终正确、修复、误伤、提议送达率和实际修改率，但不以送达/修改越多越好为优化目标。

## 7. A5：补上主流程真正缺少的稳健重判

当前新A5没有进入本轮实际实验。[S8] 不应继续让它排在无限的配置验收之后。

推荐只做一个小候选：**F路径发生语义分歧时的原题关键前提复判**。

1. 复用F已有的不同路径或不同标签映射结果，映回同一原生语义；不再生成大型新视图框架。
2. 出现分歧时，给复判者当前完整原文、问题和竞争答案，不以“某答案来自强专家/得到最多票”制造权威偏置。
3. 只问“当前前提中的哪项关系决定该答案”，先输出原生标签，再给可选简短依据。
4. 最终答案按固定原生映射输出。没有可用分歧轨迹的题按预定固定流程处理，不能根据gold挑选复判。

用同数量额外原题重答作对照，避免把多一次推理当成新机制。额外加入本格式下的无关变化与固定问题、关键前提变化对；不把不支持格式的失败用来否定该头。

此方案是待验证的F扩展，不称旧F已经学会不变性，也不保证新复判必定提高成绩。它的开发优先级高于继续在八个诊断输入上打磨编辑器。

## 8. A3与A4怎么安排

### A3

当前主流程保留旧目录比较。先尝试在**完整原题**上比较两个候选的决定性支持与反证，减少编辑有效性带来的额外负担；与普通重评分同预算比较。

确实需要再测局部编辑时，程序只做确定的目标片段操作，保留原题和明确标识的探针题，不让模型重写整个病例。原题无编辑控制必须独立执行；拒绝的编辑按具体原因分为格式、目标边界、主体/时间冲突、医学语义未决，不将它们统一称为反事实推理失败。

八题是小开发面板，完整母题数量更小。不为此要求各个小组都统计显著，但也不把一题波动包装成胜利。需要增加信息时，扩充合法诊断开发来源或母题，而不是在相同八题上无限调参。

### A4

沿用已通过的typed patch与求解器。当前121题没有其适用输入；它仍是有条件的工具专家。[S8] 不为凑五个方框去补造临床生理参数，也不重写已有效的数值内核。它的专项结果单列即可，主方法暂时不要求五个角色每题同时激活。

## 9. 下一轮按信息收益排序，而不是按工程阶段编号推进

| 优先级 | 实际行动 | 首要产物 |
|---|---|---|
| 1 | 将辅助字段检查降为警告，完成已有A1及控制的可评分开发通路 | 第一张真正包含A1裁决结果的质量表 |
| 2 | 短决策与确定性原生输出的读出实验 | 是否减少集合误删、标签重写；修复与误伤 |
| 3 | 轻量A1的有效目标选择和去锚定小对照 | 是否提供B之外的信息 |
| 4 | 新A5关键前提复判，与额外重答等预算比较 | 保持与相关变化响应两侧结果 |
| 5 | 固定较有希望的组合，完整121开发回归 | 跨题型净收益及代价 |
| 6 | 增补完整同工具控制、跨母题/来源验证 | 真实方法归因与泛化证据 |

可以先用一个现有骨干快速筛方向，再用第二骨干复核；不能最终只报告获利骨干。首批质量开发可以是覆盖主要格式的一组，例如约32个输入，具体数量按母题完整性和已有合法数据决定。随后回到完整121输入，不能用小批替换主表。

有意义的失败应推动下一假设：若提议本身都错，优先改善支持获取或调用已存在的真实知识工具；若提议对但裁决错，优先比较/读出；若只有格式错，修输出路径。不要对这些不同问题都增加一个validator。

## 10. 如何允许科研探索，而不把开发调优当最终证明

开发集允许反复看结果、调prompt和预算。三题技术测试只证明通路能不能工作，不承担方法采用判断。各实验变体用普通短配置名和结果表记录，必要的老结果保留；不再为每次自然语言提示调整生成一整套审批链。

评价目标是净收益，不是绝对零误伤：对同样的唯一输入，正确计数变化等于修复减误伤；原生单元均分需按原协议另算，不能混用。某变体允许少量改坏，若总体更好且相关变化/保持表现合理，就值得扩大验证。

当前阶段不必因一个小面板、一个骨干没有超过控制就永久停止研究。也不能以另一骨干或一个来源的最佳点宣称通用有效。最终固定方法后，再做同信息/同工具/同预算对照与未用于选择的评估。

独立范围若暴露历史无法确认，可如实改称开发或回归，并安排新的母题/来源分割；无须把无穷无尽的历史访问证明当成继续研究的前置条件。

## 11. 简化成本与运行机制

本轮实际成本见[S9]，模型累计墙钟不等于整个工程过程耗时；不能据调用数直接推算浪费百分比。

研究版只需要：每次输入、输出、配置、成本和状态随结果落盘；单题错误不中断其他题；复用确定相同的请求；避免无意义重复加载模型或导出全部历史日志。已有引擎退出修复直接复用。

遇到短解释字段上限问题，先删除非必要上限。真正连续推理被总token截断时，允许开发期增大预算或分成短结论生成；控制组获得对应预算并报告实际使用量。不能预设“任何加token都禁止”，也不能认为加token会解决只有一百多token的来源约定错误。

## 13. 本次不作的保证

没有服务器原文与模型响应，不能断言六条A1内容有几条医学正确；不能预报放宽规则会涨多少分；不能承诺确定性读出会修好记录中的每一条漏选。建议的意义在于让这些问题进入可观察、可计分的实验，而不是继续被辅助约定挡住。
