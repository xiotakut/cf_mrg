# 论文写作轻量入口

2026-10-23，GitHub目录：[`xiotakut/cf_mrg/benchmarks/2026-10-22_paper_evidence_handoff`](https://github.com/xiotakut/cf_mrg/tree/main/benchmarks/2026-10-22_paper_evidence_handoff)。直接阅读本页与按表CSV即可，无需压缩包。完整原始证据留在本地；本目录只交付下述轻量范围。复制的审计材料保留形成时点，历史“未上传”表述不代表本目录的当前发布状态。

这份材料以未压缩的普通文本目录交付，供写作 agent 直接按章节取证，不需要下载或解压 ZIP。它保存全部运行登记的精简视图、14 张表的映射、额外主张、负结果与限制，并附按角色和体积规则选择的完整小型代码、配置、决策、输入和保存分数文件。未按成绩挑选案例，没有新增模型输出或评分。

## 推荐阅读顺序

1. 阅读 [方法与决策](METHOD_AND_DECISIONS.md)、[缺口与冲突](GAPS_AND_CONFLICTS.md)，明确 B 默认、C3 研究扩展、开发暴露与独立确认未执行的边界。
2. 写一张表时，先查 [表索引](writer_view/TABLE_INDEX.csv)，再打开对应 `writer_view/tables/*.csv`。每行保留 MAP-ID、分母、统计规则、保存值／重汇总值及版本限制。表间重复 MAP-ID 不能相加当样本数。
3. 用 [证据索引](EVIDENCE_INDEX.csv) 按 MAP-ID 或 run_id 查实际交付的小文件。`starter_status` 明确区分完整小文件、必须取完整归档的层和原件仅索引。代码、配置、保存分数是证据；本说明和既有论文都不是独立保证。
4. 对照对应专项检查：[七系统基线](audit/baselines/findings.md)、[决策头及 A4](audit/heads/findings.md)、[CF-MoA](audit/cfmoa/findings.md)。核查历史方案时用全部 [运行索引](writer_view/RUN_INDEX.csv) 及 [额外主张](writer_view/ADDITIONAL_CLAIMS.csv)，不要只看当前表。
5. 需要某条模型原答、检索上下文或失败/重试链时，以 MAP-ID、run_id 或输入ID向本地证据持有者请求对应范围及 SHA；无需先发布整个大包。需要完整重汇总时另行取得完整相关证据层。大证据目前只保留在 data4 本地目录，服务器路径不是 GitHub 可取链接。

## 这份材料可以支持到哪一步

它能帮助写作 agent 确定章节结构、方法身份、准确分母、表格数值的来源、取舍原因和证据边界。被复制的小证据文件保留完整内容及 SHA；gzip 源会展开为可浏览文本。大文件没有截取一段后冒充全量交付。

它不包含全部逐项分数、实际提示、原始响应或大型清单，不能单靠它独立重验所有论文表，也不能声称已逐条检查模型原文。随附的重汇总脚本展示统计规则，执行完整重汇总需完整归档及其 FILE_MANIFEST。某份被保留的历史说明指向归档中的其他文件时，查证据索引判断本轻量目录是否真正包含目标；未包含不等于未执行。

## 放到 GitHub 的文件

可以将本目录全部普通文本文件放在一个独立目录，按 [逐文件清单](FILES.csv) 核对；该目录通过普通Git提交交付，完整大证据未纳入本次提交。推荐入口为本文件、两份主说明、三个专项报告、按表 CSV 与小证据索引。本轮 GitHub 交付只使用这个轻量目录；完整大证据留在 data4 本地，按需提供具体范围。直接给其他 agent 本 README 和表格的普通文本链接，不提供 ZIP 附件。

选择规则、体积上限、未交付原因和生成输入 SHA 见 [选择与核验](SELECTION_AND_VALIDATION.json)。这些规则按角色与大小工作，不按结果好坏筛选；数值向量等原本未交付层也不会因本导航而恢复。
