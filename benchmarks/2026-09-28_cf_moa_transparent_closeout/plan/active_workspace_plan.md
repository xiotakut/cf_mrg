## 3. 为什么不建议删“效果不好”的数据

删除模型答错题、B 正确而 C3 错误的题、某个模型下负增益来源，或者反复试子集直至上涨，都会使评测成员依赖结果。这种结果只能说明筛选规则偏好当前方法，不能说明新病例上方法更好。

如果此时看到 M4 下降就只保留 M5，或 M4 选 C4、M5 选 C3，得到的是经过当前结果选择的配置。可以明确标为开发选择，并保留被比较结果；不能当成事前固定的跨骨干验证。

同理，R5 数量多不构成删除理由；本项目已有主指标以原生单元等权，不应再为提升成绩重新改类别权重。新的 source-macro 或类别平均可以附加报告，但不能取代已冻结主指标。

## 4. 什么情况可以调整评测范围

| 情况 | 可以采取的操作 | 必須保留的证据 |
|---|---|---|
| 输入文件损坏、缺失题干/必须证据 | 修正数据视图；无法恢复时列客观不可评价记录 | 问题不依赖某个模型的正确性；全部方法同一规则 |
| 标签确有冲突或原数据勘误 | 单独构建更正版敏感性分析 | 原标签、纠正证据、影响范围、所有方法重算结果 |
| 真正错误重复、非独立拷贝 | 使用预定去重规则建立附加视图 | 不把合法不同干预或同病例多个目标误删 |
| 研究对象定义上不属于目标任务 | 建立明确的机制/任务范围视图 | 定义依据来自题面与任务合同；完整结果与覆盖率仍报告 |
| 模型失败、invalid、不可用、被误导、候选没有正确答案 | 不作数据质量剔除，保留分母 | 这些是方法表现或覆盖问题 |
| 方法在某来源下降 | 全来源分层分析，不自动排除 | 同时展示正负来源，不以符号决定成员 |

独立于当前模型输出的规则只是必要条件，不足以消除事后选择：如果规则或范围是在看到结果后提出，应明确标记为 exploratory/post-hoc。不能把事后提出的范围伪装成预先注册任务。

当前已核对材料没有提供一份足以支持具体删题的客观勘误清单。本次不据结果臆造“低质数据”名单。

- full_results.md：完整六臂及B−C0、C3−B、C3−C2。
- all_source_results.json：所有来源，不按成绩删选。
- format_input_results.json：输入级格式分层，与原生指标明确区分。
- family_effect_intervals.json：真实全量配对区间。
- attributed_costs.md：每方法成本与共享归属。
- scope_and_limitations.md：开发暴露、事后分析、覆盖限制与未执行确认。
- data_issues.jsonl：只有独立证据的问题；不存在就为空文件。

本轮不需要新的大框架、额外模型调用或重复源码审计。目的是真实收尾，不是把筛选结果包装成模型进步。
